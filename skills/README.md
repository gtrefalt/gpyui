# gpyui agent skills

Two installable skills help coding agents build native desktop applications
through **gpyui's Python API**, with actual GPUI Kit controls:

| Skill | Use it for |
| --- | --- |
| [gpyui](gpyui/SKILL.md) | Installation, all 72 component contracts/examples, composition, State, events, asyncio, lifecycle, styling and runnable applications |
| [gpyui-design-guides](gpyui-design-guides/SKILL.md) | Desktop task hierarchy, panes, forms, spacing, semantic colors, data views, interaction states, copy and design review |

They are inspired by [GPUI Kit's skills](https://github.com/longbridge/gpui-kit/tree/3a142844d3661159964dce9e5512ca9a40286160/skills),
with original guidance adapted to the Python binding. They target gpyui 0.4.0,
and clearly distinguish Python support from unbound upstream capabilities.

## Install with the skills CLI

From your application project:

```bash
npx skills add gtrefalt/gpyui --skill gpyui --skill gpyui-design-guides
```

Select your coding agent and project/global scope in the installer. This command
installs instructions, not the Python package; install gpyui using `uv add` as
described in [the runtime guide](gpyui/references/runtime.md). The
[skills CLI](https://github.com/vercel-labs/skills) requires Node.js for `npx`.

## Manual installation for Codex

Copy **the whole skill directories**, including `references/` and `scripts/`,
into your application's `.agents/skills/` directory:

```bash
git clone --depth 1 https://github.com/gtrefalt/gpyui.git /tmp/gpyui-skills
mkdir -p .agents/skills
cp -R /tmp/gpyui-skills/skills/gpyui .agents/skills/
cp -R /tmp/gpyui-skills/skills/gpyui-design-guides .agents/skills/
```

For another agent, use its supported skill directory. Copying only SKILL.md
omits the API context. The bundled references and recipes work outside this
repository; external documentation links are additional reading.

## Use

Ask, for example: "Use the gpyui and gpyui-design-guides skills to build a light
native settings app with state-bound fields and asynchronous saving."

The technical skill starts with setup and ownership, then directs the agent to
the relevant component family and recipe. The design skill starts with the
user's task and finishes with an interaction/design checklist. An agent must
still verify the installed package version and run the application on a desktop;
the skills do not add runtime features or certify native accessibility.

## Maintain

The component family references are generated by the same script as the public
component documentation, from the Python classes and runnable specimens:

```bash
just docs-generate
just skills-check
just docs-check
```

Update the hand-written guidance and skill version markers when changing the
API. Keep examples executable, bundle any local references, and verify callback
cleanup against application shutdown. CI detects stale component references,
missing local links, invalid examples, and recipe logic regressions without
building native wheels. New wheels are built only for version tags.
